# Native App Workflow

Use this workflow for mobile, desktop, television, watch, spatial, embedded, or other native interfaces.

## Capability and environment

Use available emulator, device, accessibility-inspector, or computer-control tools. Record device model, OS, app build, display scale, orientation, window size, input, theme, text settings, and network/data fixture.

- Test real device or emulator behavior when possible; browser resizing is not a substitute.
- Inventory screens, windows, sheets, menus, system integrations, roles, adaptive layouts, and canonical data exemplars.
- Exercise platform navigation, back/close behavior, menus, keyboard/pointer/touch input, safe areas, virtual keyboard, rotation, resize, scaling, focus, and relevant accessibility settings.
- Inspect every instance in context and record shared evidence only for proven-equivalent component variants.

Classify actions before using them. Persistent settings, account changes, messages, purchases, uploads, sharing, publishing, and destructive actions require action-time approval. Use fixtures or supplied recordings to assess unsafe states without executing them.

## Limited access

If native control is unavailable, review supplied screenshots, recordings, accessibility exports, and source code. Mark hidden states, semantics, focus behavior, assistive technology, performance, hardware behavior, and true-device rendering untested. A recording can support motion and timing evidence but cannot prove semantics or alternate settings.
